# OperationInAI 使用文档

## 启动

```powershell
npm.cmd run dev
```

访问：

```text
http://localhost:4173/
```

## 推荐使用顺序

1. 在“数据清洗 / 支持配置库”中维护认证配置和清洗规则。
2. 在“数据清洗 / 数据源配置”中维护 API、数据库或文件数据源。
3. 在同页配置字段映射，必要时点击“测试联通”从响应体选择字段。
4. 在“数据清洗 / 业务配置”中为业务编排唯一业务流。
5. 在“数据展示”中选择业务和时间范围查看业务数据。
6. 在“智能分析”中配置模型，选择业务和字段生成分析。
7. 在“智能搜索”中维护知识源并提问。

## 数据清洗

### 认证配置

当前默认支持通用无认证、API Cookie、数据库账号密码三类配置。数据源只引用认证名称，Cookie 或账号细节在认证配置中维护。

### 字典集

字典集用于维护可复用的枚举、列表或业务维表，例如产品列表、部门列表、区域列表、版本列表。它放在“数据清洗 / 支撑配置库”中，和认证配置、清洗规则同级维护。

字典集由三部分组成：

- 字典名称：供其他模块引用时选择，例如“产品列表”。
- 字典分组：用于支撑配置库里的分组展示和折叠管理，可按业务口径自由输入，例如业务字典、产品字典、团队字典；不直接参与字段值匹配。
- 表头字段：根据字典值 JSON 自动生成，例如 `产品部,产品名,别名列表,版本号`。
- 字典值 JSON：数组形式，每一行是一条字典记录。

产品列表示例：

```json
[
  { "产品部": "交易产品部", "产品名": "支付网关", "别名列表": "pay-gateway,payment-api", "版本号": "v3" },
  { "产品部": "订单产品部", "产品名": "订单中心", "别名列表": "order-center,order-api", "版本号": "v2" }
]
```

字段值过滤和清洗规则可以引用字典集。比如在字段值过滤中选择“产品列表”的“别名列表”作为匹配列，并把范围列设为“产品部”、范围值设为“交易产品部”，系统就只会用交易产品部下的产品别名参与匹配。匹配列中的逗号、分号或竖线分隔值会被自动拆开参与匹配。

字段值过滤有两种字典匹配方向：

- 字段值在字典列中：例如字段值 `pay-gateway` 命中“产品列表 / 别名列表”中的任意别名。
- 字典值在字段内容中：例如字段内容 `支付网关 pay-gateway v3 告警` 包含字典列中的 `pay-gateway`。

### 数据源配置

数据源支持：

- API：配置 URL、方法、Query/Header/Body、分页参数模板和响应路径。
- 数据库：配置表名或查询目标，后续可扩展为真实连接配置。
- 本地文件：配置文件路径。

数据源只描述“如何完成一次基础调用”：认证、地址、请求方法、入参结构、分页参数字段、响应路径、字段保留和字段映射。查询多少页、是否按数据库记录循环、并发几路、每路负责哪些页，统一放在业务配置的“数据源执行策略”中控制。

API 数据源的“测试联通”规则：

- 当数据源地址是完整 `http://` 或 `https://` URL 时，后端会发起真实请求。
- 当地址是相对路径、表名或文件名时，系统使用模拟响应辅助字段映射配置。
- 测试结果会标明“真实请求”或“模拟响应”，并展示响应字段、样本记录数和响应体。

请求入参会根据请求方法自动调整：

- `GET`、`DELETE`、`HEAD`：展示 Query 和 Header，隐藏 Body。
- `POST`、`PUT`、`PATCH`：展示 Query、Header 和 Body。

入参来源使用方式：

- 固定入参：直接填写 Query/Header/Body。
- 数据库查询：选择数据库来源，勾选字段后可生成 SQL 和字段映射。
- 上游数据源：选择上游数据源，系统根据该数据源字段映射或样例字段提供候选字段。
- 业务流上下文：使用 `context.start_time`、`context.end_time`、`context.businessName` 等上下文字段驱动调用。
- 字典集：选择一个或多个自定义字典集，使用 `字典名称.字段名` 作为入参来源，例如 `产品列表.产品名`。
- 业务节点输出：选择当前业务流中的一个或多个上游节点，字段会带节点名前缀，适合一个数据源在调用前依赖多个并发节点的输出。

业务流上下文是每次业务流运行时系统自动带上的公共变量，不需要从某个数据源查询。当前可用字段：

- `context.start_time`：本次业务流时间窗口开始时间，常映射到 `startTime`、`beginTime`。
- `context.end_time`：本次业务流时间窗口结束时间，常映射到 `endTime`、`finishTime`。
- `context.businessName`：当前业务名称，常用于业务标识或查询过滤。
- `context.batchId`：本次运行批次号，常用于链路追踪、幂等或日志关联。
- `context.tenant`：当前租户。
- `context.env`：当前环境，例如 `prod`、`test`、`dev`。

勾选“来源字段”后点击“生成入参与过滤”，系统会自动生成入参字段映射 JSON 和建议过滤条件，用户再按实际接口调整即可。

入参字段映射 JSON 表示“来源字段如何写入请求入参”：

```json
[
  { "from": "service_id", "to": "body.serviceId" },
  { "from": "owner", "to": "query.owner" }
]
```

占位符变量 JSON 用于替换 Query/Header/Body 中的 `{{变量名}}`：

```json
[
  { "name": "start_time", "source": "mapping", "from": "context.start_time" },
  { "name": "env", "source": "custom", "value": "prod" },
  { "name": "product", "source": "dictionary", "from": "产品列表.产品名", "mode": "array" }
]
```

其中 `source=custom` 会直接使用 `value`；`source=mapping` 表示变量值来自业务流上下文、上游数据源或数据库记录字段，测试接口会保留可追踪占位符，真实编排执行时再按来源逐条填充。
`source=dictionary` 表示变量值来自字典集，`from` 写成 `字典名称.字段名`，例如 `产品列表.产品名`。

字典列存在多个值时，可用以下方式组合：

- `mode=join`：默认方式，按 `separator` 拼接；未配置 `separator` 时使用英文逗号。
- `mode=array`：保留为数组，适合 JSON Body 中的列表字段。
- `mode=first`：只取第一个字典值。
- `mode=newline`：按换行拼接。
- `mode=template`：用 `template` 对每个值渲染，例如 `product={{value}}`；可配 `asArray=true` 返回数组。

如果某个入参字段本身是 JSON 字符串，需要在平台入参 JSON 中转义内部双引号。例如实际接口需要：

```json
{
  "filter": "{\"product_service\": \"ROMAConenct,ServiceStage\"}"
}
```

平台中可以配置为：

```json
{
  "filter": "{\"product_service\": \"{{products}}\"}"
}
```

系统会先解析外层入参 JSON，再替换字符串内部的 `{{products}}`。如果 `products` 来自字典列并使用默认 `join` 模式，最终会得到 `{"product_service": "ROMAConenct,ServiceStage"}` 这样的字符串值。

页面中的占位符变量输入框可为空；为空表示不启用占位符替换。鼠标移到问号时会显示 JSON 填写格式和字段含义说明。

### 字段映射

字段映射用于把源字段转换为目标业务字段。可以配置：

- 响应数据路径。
- 保留全部记录或按条件过滤。
- 源字段、目标字段、字段类型、默认值。
- 展示别名：只用于数据展示表头、字段筛选和分析字段选择；清洗、过滤、主键、落库仍使用目标字段名。
- 字段跳转：开启后，数据展示表格中该目标字段会显示为链接。跳转链接模板支持 `{{value}}`、`{{businessName}}`、`{{目标字段名}}`，也可以在“链接占位符 JSON”中配置占位符来源。
- 可选清洗规则。字段映射中的源字段会作为规则输入，目标字段会作为规则输出。
- 映射方式：默认“每个对象生成一条记录”；当 API 返回 list，需要把多条对象中的某个值汇总到同一个目标字段时，选择“多对象合并到同一条记录”。
- 字段保留策略：保留全部字段，或只保留测试响应中勾选的字段。
- 字段值过滤：在保留字段基础上继续设置每个字段的值过滤，支持完整匹配、模糊包含、前缀、后缀和正则，也可以引用字典集中的某一列作为匹配值来源。
- 存储策略：不单独存储，或存储到原始表、清洗表、指定表。

“同步当前数据源”会按当前选中的数据源配置执行一次采集和响应解析，并把字段保留、过滤、映射预处理后的记录数写入同步日志；它用于验证这一条数据源链路，不等同于执行业务流编排。

字段跳转示例：

```json
[
  { "name": "service", "source": "field", "from": "service_id" },
  { "name": "env", "source": "custom", "value": "prod" },
  { "name": "product", "source": "dictionary", "from": "产品列表.产品名", "mode": "first" }
]
```

配合链接模板 `/service/detail?service={{service}}&env={{env}}&product={{product}}` 使用。`source=field` 从当前业务表行读取字段值；`source=custom` 使用固定值；`source=dictionary` 从字典集列中取值。未配置占位符 JSON 时，系统会自动尝试用当前行字段名、字段展示别名、`value` 和 `businessName` 替换同名占位符。

多对象合并映射适合这类响应：

```json
{
  "data": {
    "items": [
      { "value": "应用服务|ROMAConnect|2.2.0" },
      { "value": "应用服务|ROMAConnect|2.3.0" },
      { "value": "应用服务|ServiceStage|2.2.0" }
    ]
  }
}
```

配置方式：

- 响应数据路径：`data.items[]`。
- 源字段路径：`data.items[].value` 或 `value`。
- 目标字段名：例如 `matched_products`。
- 映射方式：选择“多对象合并到同一条记录”。
- 对象过滤条件：例如 `value contains ROMAConnect || value contains ServiceStage`，也可以留空表示全部对象参与。
- 聚合方式：选择“去重后拼接”时会输出 `应用服务|ROMAConnect|2.2.0,应用服务|ROMAConnect|2.3.0,应用服务|ServiceStage|2.2.0`；选择“取第一个值”只输出第一条命中的值；选择“输出数组”会保留数组结构。

如果某个数据源中存在任意一个“多对象合并”映射，该数据源的映射结果会产出一条目标记录；同源中的普通映射字段会从第一条响应对象取值，用于补充来源、时间等标量字段。

#### 过滤条件表达式

过滤条件用于从数据源响应中筛选需要保留的记录。系统会先按“响应数据路径”定位记录集合，再对每条记录执行过滤条件。

响应数据路径示例：

```text
data.items
data.items[]
data.detail.list[]
sheets[0].rows
```

字段路径写法：

```text
level
service.owner
service.metadata.region
data.items[].level
data.metrics[].labels.region
rows[0].name
```

支持的操作符：

```text
field == value
field != value
field > value
field >= value
field < value
field <= value
field contains value
field in [a,b,c]
field exists
field in dict(字典名称.字段名)
field contains dict(字典名称.字段名)
```

支持 `&&` 和 `||` 组合：

```text
level in [P0,P1] && duration > 300
name == cpu || name == mem
owner exists && status != closed
name in dict(产品列表.别名列表 where 产品部=交易产品部)
title contains dict(产品列表.别名列表)
```

嵌套数组和单条对象内嵌 list/dict 的写法：

```text
data.metrics[].name == cpu && value >= 90
data.items[].service.owner exists
data.items[].tags[] contains prod
```

说明：

- `[]` 表示数组中的任意元素。
- 字符串可以不加引号，例如 `level == P0`。
- 值里包含空格时建议加引号，例如 `owner == "平台 团队"`。
- 当前不支持括号优先级表达式，例如 `(A || B) && C`。复杂条件建议拆成更简单的条件。

#### 清洗表说明

清洗表是原始数据和最终业务表之间的中间结果表。它保存已经完成过滤、字段映射、默认值填充、规则转换后的数据，主要用于排查清洗逻辑、追溯数据来源和复跑业务流。业务表更偏展示和分析，清洗表更偏过程留痕和质量控制。

### 清洗规则表达式

清洗规则用于描述“输入值如何被清洗为输出值”，例如格式标准化、枚举转换、补默认值、去重、合并、正则提取或模板组合。规则本身不绑定输入字段和输出字段；在数据源字段映射中选择规则后，源字段自动作为规则输入，映射字段自动作为规则输出。

表达式格式：

```text
动作(参数)
```

当前规则动作：

```text
trim       去除首尾空格
lower      转小写
upper      转大写
enum       枚举转换
default    空值默认
filter     条件过滤
date       时间格式化
number     数值转换
enrich     关联补齐
dedupe     多值去重
merge      多值合并
extract    正则提取
combine    模板组合
```

常见示例：

```text
trim
enum(P0=高,P1=中,P2=低)
default(未分配)
date(YYYY-MM-DD HH:mm:ss)
number(seconds_to_minutes)
extract(\d+)
merge(,)
combine({{service.name}}-{{level}})
```

### 字段映射与清洗规则

字段映射只负责三件事：

- 选择源字段路径。
- 配置目标字段名和默认值。
- 引用一个已定义的清洗规则。

数据源测试结果会展示“字段映射与清洗后的样本”，用于确认每个字段引用的规则是否符合预期。去重、合并、截取、组合等都应作为清洗规则维护，而不是在数据源映射中重复配置。

规则字段含义：

- 规则动作：系统内置的处理动作。
- 参数配置：动作需要的补充参数，例如枚举映射、默认值、时间格式、关联表字段等。

### 业务流

一个业务对应一个业务流。业务流节点可表示：

- 上下文节点：时间窗口、租户、批次号。
- 数据源节点：采集 API、数据库或文件数据。
- 规则节点：清洗、映射、关联补齐。
- 输出节点：写入原始表、清洗表和业务表。

节点支持串行、并行、条件分支和汇聚。

业务流运行时会按 DAG 连线执行，而不是只按页面顺序展示：

- `context` 节点会输出本次运行上下文，例如 `start_time`、`end_time`、`businessName`、`batchId`、`tenant`、`env`。
- `source` 节点会执行数据源取数、响应解析、字段保留、字段值过滤和字段映射。
- `rule` 节点会读取上游节点记录；如果节点或规则配置了字段映射，会再次应用映射和清洗规则，否则默认透传上游记录。
- `join` 节点会汇聚多个上游分支输出，适合多条并行分支结束后再进入统一输出。
- `output` 节点会把上游最终记录作为业务表数据写入系统业务数据。

条件边的表达式使用同一套过滤语法，例如 `severity in [P0,P1]`。条件不满足时，下游节点会跳过；普通串行边可不填写条件。多个并发上游都需要作为入参来源时，建议在数据源入参来源中选择“业务节点输出”，并在业务流里用显式连线表达依赖关系。

数据源节点可以在业务流里覆盖执行策略，用于处理大批量 API 采集和数据库记录驱动调用：

- 分页查询：`不分页` 表示只请求一次；`页码分页到最后一页` 会按页码递增；`Token 分页到最后一页` 会从响应体路径读取下一页标识。
- 查询总页数：业务本次要查询的页数。已知总页数时，系统按总页数生成分页任务；未知页数时，可填 0 并依赖“是否还有下一页路径”或最大页数停止。
- 每并发页段：每个并发任务负责多少页。例如查询总页数 100、每并发页段 50，会生成两个并发页段：`1-50` 和 `51-100`。填 0 时按并发数自动均分。
- 最大页数：防止接口分页异常导致无限请求。即使接口一直返回有下一页，达到最大页数后也会停止。
- 入参迭代：`单次调用` 适合固定入参；`按记录逐条调用` 适合先从数据库表读取多条记录，再按每条记录调用 API；`分批次批量调用` 适合接口本身支持批量入参。
- 批量大小：每批取多少条来源记录组成一次 API 调用。
- 并发数：同一数据源节点允许同时执行的请求或批次数，需要结合接口限流和数据库连接池配置。
- 记录锁字段：当多个任务并发读取同一张表时，用主键或唯一业务键避免重复处理同一条记录。
- 锁策略：`不加锁` 适合只读或单线程；`跳过已锁记录` 适合多 worker 并发消费；`乐观锁版本校验` 适合通过版本号或更新时间避免覆盖更新。

推荐分工：数据源配置负责地址、认证、请求入参、分页参数模板、响应路径和字段映射；业务流的数据源节点负责运行时策略，例如是否自动翻页、查询总页数、页段分片、是否由数据库记录驱动、并发数、批量大小和锁策略。

态势总览的筛选字段是全局配置，不绑定某一个业务。进入“态势总览 / 筛选配置”后，可以维护多个全局筛选项：

- 筛选名称：页面上展示的名称，例如“环境”“区域”“等级”“归属对象”。
- 字段名：最终业务数据中的字段名。对象记录可写字段路径；数组记录会按业务字段表头匹配。
- 控件类型：下拉单选、多选或文本搜索。
- 取值来源：从业务数据自动提取、引用字典集或手工枚举。
- 默认展示：是否显示在态势总览顶部筛选区。

筛选执行规则是“字段存在才过滤”：某个业务或某条记录没有对应字段时，该筛选条件会自动跳过，不会把该业务误过滤掉。

时间段筛选也在态势总览全局配置中维护候选字段，例如 `event_time,created_at,updated_at,time,时间`。系统会按顺序查找这些字段；没有候选时间字段的记录会跳过时间过滤。

输出与落库配置说明：

- 输出方式：`写入/更新业务模块` 会进入系统业务数据，供态势总览、数据展示和智能分析使用；`输出文件` 和 `输出 API` 用于后续扩展外部交付。
- 主键字段：支持单字段或多字段组合。多字段用英文逗号分隔，例如 `event_id,source_id`。
- 写入策略：按主键更新会使用主键字段定位同一条业务记录；追加写入会保留每次执行结果；覆盖写入会以新结果替换旧结果；仅预览不保存只用于调试。
- 去重策略：按主键去重使用主键字段；按字段组合去重需要填写“去重字段组合”，例如 `product_dept,product_name,event_time`；不去重会保留所有记录。

## 数据展示

选择业务模型后，可以使用：

- 时间字段：用于指定业务数据中的时间匹配字段。
- 时间预设：最近 24 小时、7 天、30 天。
- 开始时间/结束时间：通过时间组件选择，不需要手动输入自然语言。
- 排序：风险等级、发生时间、影响范围。
- 字段搜索：按事件、等级、对象等表格字段搜索。

## 运行安全与后端能力

### 访问令牌与角色

本地开发环境默认不配置令牌，此时后端按管理员权限运行，方便直接调试页面。

部署到共享环境或生产环境时，建议配置：

```powershell
$env:OPERATION_API_TOKEN="your-token"
$env:OPERATION_API_ROLE="admin"
```

接口请求需要携带：

```text
X-Operation-Token: your-token
X-Operation-User: 用户名或系统账号
```

启用令牌后，权限角色由服务端环境变量决定，不信任浏览器传入的 `X-Operation-Role`。如果需要多个令牌和不同角色，使用：

```powershell
$env:OPERATION_API_TOKENS='{"reader-token":{"role":"reader","user":"viewer"},"operator-token":{"role":"operator","user":"ops"},"admin-token":{"role":"admin","user":"admin"}}'
```

角色含义：

- `reader`：查看配置、业务数据、分析结果和审计日志。
- `operator`：执行新增、测试、同步、分析等常规操作。
- `admin`：修改存储配置、删除配置、管理高风险资源。

未配置 `OPERATION_API_TOKEN` 或 `OPERATION_API_TOKENS` 时不会拦截请求；配置后，令牌不匹配会返回 401，权限不足会返回 403。本地无令牌开发模式下，才会读取 `X-Operation-Role` 方便调试。

前端请求会自动从浏览器 `localStorage` 读取以下值并写入请求头：

```text
operation_api_token
operation_api_user
```

内网联调时可在浏览器控制台执行：

```javascript
localStorage.setItem("operation_api_token", "your-token");
localStorage.setItem("operation_api_user", "pj");
```

### 密钥加密与脱敏

认证配置、模型 API Key、数据库密码等敏感字段会在写入本地运行存储前加密，格式类似 `enc:v1:...`。接口返回给前端时只返回脱敏值或空值，不回显真实 Cookie、密码和 API Key。

建议在部署环境固定配置：

```powershell
$env:OPERATION_SECRET_KEY="长度足够的随机密钥"
```

如果不配置，系统会使用本地开发密钥；这适合调试，不适合作为正式环境长期密钥。更换密钥前需要先导出或迁移旧敏感配置，否则旧密文无法用新密钥解密。

### 审计日志

后端会记录主要写操作，包括新增、编辑、删除、测试同步、分析触发等。审计日志包含用户、角色、请求方法、路径、操作状态和简要对象信息，可通过：

```text
GET /api/audit-logs
```

查看最近记录。默认最多保留 1000 条，可通过 `OPERATION_AUDIT_LIMIT` 调整。

### 存储适配器

当前运行时已经通过存储适配器读写数据：

- 本地 JSON 存储：默认可用，文件位于 `server/data/runtime-store.json`。
- SQLite 数据库存储：内置可用，默认文件位于 `server/data/runtime-store.sqlite`。在“支持配置库 / 存储配置”中新建 SQLite 存储并设为当前后，后续写入会进入 SQLite；本地 `runtime-store.json` 不会被 SQLite 运行数据覆盖，系统会用 `server/data/storage-pointer.json` 记录当前存储指针。
- PostgreSQL / MySQL / MariaDB / SQL Server / Oracle：页面配置项已保留，当前后端不会假装写入。设为当前存储时如果未接企业驱动，会返回 501，避免误以为已经持久化到外部数据库。

后续接入企业数据库时，只需要在存储适配器中实现对应数据库的 `read/write/probe`，不需要改动上层业务接口。

### 正则安全限制

过滤条件和清洗规则中支持正则，但后端会阻断明显高风险表达式，例如过长正则、嵌套量词和连续 `.*`。默认正则最大长度为 180，可通过：

```powershell
$env:OPERATION_MAX_REGEX_LENGTH="180"
```

调整。被阻断的正则会按“不命中”处理，避免异常表达式拖慢同步任务。

## 出参字段值过滤、临时取值与聚合输出

字段值过滤可以按“先取判断值、再判断命中、最后决定输出”的方式配置：

- 过滤前清洗规则：可先引用清洗规则对字段值做一次转换，再进入过滤判断。
- 过滤取值方式：可直接使用字段值，也可按分隔符取片段，或用正则提取片段。按分隔符取片段时，片段序号从 1 开始。
- 字典匹配：可用“字段值在字典列中”判断临时值是否存在于字典列，也可用“字典值在字段内容中”判断字段内容是否包含任一字典值。
- 命中后输出：可保留原字段值、只保留命中的字典/片段内容，或保留过滤取值。
- 聚合输出：可把多条命中记录合并成一个值，并配置分隔符和是否去重。

示例：API 返回 `value=应用服务|ROMAConnect|2.2.0`，想用中间的 `ROMAConnect` 去匹配“产品列表.别名列表”，但最终仍输出原始 value。

```text
字段：data.items[].value
过滤取值方式：按分隔符取片段
分隔符：|
片段序号：2
引用字典集：产品列表
匹配列：别名列表
字典匹配：字段值在字典列中
命中后输出：保留原字段值
聚合输出：命中记录合并为一个值
聚合分隔符：,
```

如果只想输出命中的产品别名，把“命中后输出”改为“只保留命中内容”即可。

## 通用清洗动作参数

清洗规则动作保持通用语义，不绑定具体业务字段：

```text
strip_html(remove_script=true; remove_style=true; decode_entities=true; collapse_whitespace=true)
split_dedupe_join(separator=,; joinSeparator=,; dedupe=true; sort=true; limit=0)
replace_all(pattern=\d; replacement=#; flags=g)
enum(caseInsensitive=true; roma=ROMAConnect,apm=APM)
```

- `strip_html`：移除 HTML 标签，可默认移除 `script/style` 内容、解码常见 HTML 实体并压缩空白。
- `split_dedupe_join`：对单个字段值内部的分隔列表执行“拆分、去空、去重、可选排序、可选限长、合并”，适合执行人、标签、产品列表等多值字符串。
- `replace_all`：对字段值做正则全局替换，适合脱敏、统一字符、删除固定噪声。
- `enum`：枚举映射可通过 `caseInsensitive=true` 开启大小写不敏感匹配；未命中时保留原值。

参数既可以写成 `key=value; key=value`，也可以写成 JSON 对象；简单动作仍可只写原来的字符串参数。

## 存储切换与旧数据处理

支持配置库中的“存储配置”用于选择系统当前使用的存储位置。默认是本地存储，也可以新增一个数据库存储。

切换存储时需要选择旧数据处理策略，SQLite 会按策略生成目标存储快照：

- 复制配置数据：复制数据源、认证、字段映射、清洗规则、字典集、业务流和模型配置等配置数据；业务运行数据和历史日志仍保留在旧存储。推荐首次从本地切到数据库时使用。
- 复制全部数据：复制配置数据、业务数据、同步日志、分析结果和知识源索引等全部数据。
- 仅切换，不复制旧数据：只把当前存储指向目标存储，不复制旧数据。旧数据仍留在原存储中，切换后目标存储为空时页面可能只看到新数据。

默认本地存储不可编辑、不可删除；当前正在使用的存储不可删除。数据库密码只保存用于连接，接口返回和页面编辑时不会明文回显。
