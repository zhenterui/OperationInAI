# OperationInAI 设计文档

## 目标

OperationInAI 面向智能运维场景，核心目标是把多源数据采集、清洗、业务聚合、展示、分析和搜索串成一条可配置链路。系统当前是无外部依赖的原型实现，前端负责配置和展示，Node.js 后端提供模拟 API 与内存态配置存储。

## 模块划分

### 态势总览

态势总览不再依赖固定静态数据，而是从业务配置自动推导：

- 业务数量来自业务表和业务流。
- 数据源数量来自业务流节点和数据源配置。
- 清洗规则数量来自业务流规则节点和规则库。
- 风险与信号来自业务数据中的 P0/P1 记录和未产出数据的业务流。

### 数据清洗

数据清洗由三类配置组成：

- 业务配置：每个业务对应一个业务流，业务流使用节点描述上下文、数据源、规则和输出。
- 数据源配置：支持 API、数据库和本地文件；认证只通过认证配置名称引用。
- 支撑配置库：包含认证配置和清洗规则库。

业务流节点支持串行、并行、条件分支和汇聚。节点引用数据源或规则，最终输出到业务表配置。

### 数据展示

数据展示面向业务数据消费：

- 业务模型选择决定数据表和趋势图。
- 时间字段由业务配置推导，并提供时间预设和 `datetime-local` 时间组件。
- 支持字段搜索、风险/时间/影响排序、全量/TOP/图表视图。

### 智能分析

智能分析分为两个页签：

- 分析配置：选择一个或多个业务、多个字段、组合字段、分析方式、输出格式和提示词。
- 模型配置：维护模型厂商、模型名称、接口 URL 和 API Key，分析时可选择已配置模型。

后端当前返回模拟结构化结果，保留了业务、字段、组合字段和模型配置入参，方便后续替换为真实大模型调用。

### 智能搜索

智能搜索通过知识源配置和问题输入完成模拟问答。知识源支持 URL、本地路径或数据库来源的抽象描述。

## 数据流

```text
认证配置/模型配置/规则库
        ↓
数据源配置 → 字段映射 → 业务流节点编排 → 业务数据
        ↓                         ↓
   同步日志                  态势总览/数据展示/智能分析/智能搜索
```

## 后端接口原则

- 配置类接口采用内存存储，适合原型阶段快速调试。
- API Key 返回前会清空 `apiKey`，仅保留 `apiKeyMasked` 用于展示。
- 分析接口支持单业务和多业务入参，保持向旧字段 `businessName` 兼容。

## 后续演进建议

- 将内存存储替换为 SQLite/PostgreSQL。
- 把业务流执行器抽象为可扩展节点运行时。
- 为 API 数据源增加真实认证刷新和分页执行。
- 接入真实大模型服务，并把模型调用日志纳入审计。
- 为字段映射和过滤表达式增加可视化表达式构建器。
